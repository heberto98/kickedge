## Design

Create `kickedge/current` as orchestration around the existing code. Reuse
KickerFeatureBuilder, TeamFeatureBuilder and GameContextBuilder directly, as well
as transform/create_labels, team_prepare.aggregate and the existing providers.
Keep model code, contract, weights and the historical builders unchanged.

Current source bundle: season, schedules (identity/calendar rows including UTC
scheduled_kickoff), players (stable id, names and position), games (completed
event records with source clock, kicker labels, team sufficient statistics,
conversion counts), sources (hash/path/provider/fetched_at), generated_at.
Each game's source retains the original actual kickoff, END GAME completion,
last_event and conservative max(actual kickoff+24h,last_event) release gate.
No target statistics enter a builder. Only the target season contributes.

Live cutoff is min(generation time, scheduled kickoff minus 60 minutes), matching
the existing prediction horizon and preventing use of information not yet known.
Historical parity uses original identity kickoff and cutoff, never target outcomes.
Both routes select the same previous game records and call the same builders.
Missing required historical events is an error, not fabricated first-game history.
Ambiguous games or player identities fail. Prior team history is not proof of a
current roster; unresolved current affiliation gets an explicit warning.

Raw source cache lives under ignored data/cache/current, using nflverse approved
source URLs only. Record capture times separately from original content version;
fresh TTL cache can be reused, refresh is explicit, corrupt/missing critical data
fails. Derived event bundles keyed by source hashes and preprocessing code avoid
reprocessing unchanged data. Never overwrite the frozen historical manifests.

Optional context reuses ParlayClient and OpenMeteoClient with bounded requests.
Manual quotes always remain usable on optional failures. Exact event/player/line
binding is required for automatic quotes; unknown or DFS pricing is informational.
Weather needs resolved venue coordinates and roof; closed roofs suppress outdoor
conditions. No market or weather field enters the 82-predictor frame.

5. High-level analyze_current_prop and CLI, automatic snapshot persistence with
   provenance, manual quote fallback and optional context. Frozen 7A handles math.
6. One bounded current demo if approved sources provide a future game and current
   completed events; otherwise report the exact external limitation honestly.
7. Full previous + new suite, independent review, immutable artifact checks,
   secret/large-file checks, logical commits, push main, clean status, stop.

## Review focus

- Source lag must not silently remove known completed games.
- Target/current/future results cannot enter prior history or identity membership.
- Same-season resets, actual vs scheduled clocks and cutoff must match training.
- Provider capture/version times cannot be backdated; game/team/player and line
  matching must reject ambiguity, never silently adopt a different prop.
- Cached and derived files must be verified, and provider failures never expose keys.
